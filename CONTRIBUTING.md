# Contributing to Wake

Questions, bug observations, ideas, and offers to help are welcome in
[GitHub Discussions](https://github.com/trippwill/wake/discussions). Anyone with
a GitHub account can start there.

## Contributor access

Wake grants contributor access by invitation. GitHub calls the resulting access
**collaborator** access. The repository owner and invited collaborators can open
issues and pull requests.

If you want to contribute, start or join a discussion about the work and say how
you'd like to help. The repository owner can agree on the scope and invite you
as a collaborator. Discussions are also a place to share feedback without taking
on a change.

## Issues and pull requests

- For a bug report, include the Wake version or commit, what you expected,
  what happened, and enough detail to reproduce it with synthetic data.
- Discuss larger changes early. Keep pull requests focused and explain the
  reason for the change and the checks you ran.
- Keep financial records, credentials, tokens, and private logs out of public
  posts and fixtures. Follow the [security policy](SECURITY.md) to report a
  suspected vulnerability privately. Anyone can report without an invitation.

[AGENTS.md](AGENTS.md) describes Wake's repository rules, including signed
commits. The [development guide](.docs/engineering/development.md) covers
workspaces, tools, and checks.
